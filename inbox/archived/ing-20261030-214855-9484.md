1、自我介绍
	
2、挑一个你最熟的 Agent 项目，讲清楚从用户输入到最终输出的全链路，每一环的输入输出是什么
	
3、Harness 里 agent loop 怎么设计，终止条件除了 max_turns 还控哪些（token/耗时/预算/重复动作）
	
4、模型返回 tool_call 后，你们怎么做参数校验、权限校验、沙箱执行和结果回灌
	
5、Agent 陷入死循环或重复调用同一个工具，怎么检测和处理（状态指纹/去重/回退）
	
6、长上下文超限时，短期记忆怎么压缩，摘要丢失关键信息怎么补，跨块关联怎么保证
	
7、多 Agent 协作时，任务怎么拆分、状态怎么共享、结果冲突怎么仲裁
	
8、多个 Agent 并发改同一个文件/资源，怎么防冲突，锁粒度怎么定
	
9、Agent 执行到一半服务重启，checkpoint 存什么、放哪、怎么恢复现场
	
10、human-in-the-loop 场景，用户驳回或超时，任务怎么续跑和兜底
	
11、工具返回数据过大怎么截断/摘要，工具失败怎么重试、熔断、保证幂等
	
12、Function Calling 和 MCP 分别解决什么问题，工具太多时怎么检索和按需加载
	
13、RAG 在 Agent 里什么时机触发检索，query 改写和 rerank 怎么接
	
14、Prompt 注入怎么防，危险工具调用怎么拦截，敏感数据怎么脱敏
	
15、Agent 线上怎么评测：任务成功率、工具选错率、参数错误率、成本、耗时怎么埋点
	
16、badcase 怎么归因到模型/prompt/检索/工具，怎么回流成回归集
	
17、流式输出下，工具调用事件怎么往前端正向推送，断线重连怎么恢复
	
18、手撕算法：给一个扁平 JSON 列表（带 parent_id），恢复成树形结构并返回根节点列表

二面不像一面那样问你“知不知道”，是盯着你简历里 Agent 那一段往工程缝里捅。上下文压缩、checkpoint、并发改文件、死循环防护，全是生产环境真坑，答表面方案直接被追三层。面试官不装，懂就懂，不会就别绕。整体偏硬核，但聊透了挺爽，能感觉到团队是真在跑长任务 Agent，不是玩具 demo。
