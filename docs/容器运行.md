# 容器运行

本机现状：Docker Desktop 装在 `E:\Docker`（**不在默认路径，`docker` 命令不在 PATH**），
WSL2 后端，分配 8GB 内存。引擎版本 29.9.3。

## 1. 为什么命令要写全路径

`docker` 不在 PATH，直接敲会报"无法识别"。两种办法，选一种：

```powershell
# 办法一：临时加进当前会话
$env:PATH = "E:\Docker\resources\bin;" + $env:PATH

# 办法二：每次写全路径
& 'E:\Docker\resources\bin\docker.exe' compose ps
```

**必须加 PATH 才能构建。** 构建时 Docker 会去调 `docker-credential-desktop.exe` 拉取基础镜像的
凭据，那个程序也在 `E:\Docker\resources\bin`；不加 PATH 会直接报：

```
error getting credentials - err: exec: "docker-credential-desktop": executable file not found in %PATH%
```

## 2. 日常操作

```powershell
$env:PATH = "E:\Docker\resources\bin;" + $env:PATH
cd E:\WorkBuddy\2026-10-25-22-38-23\job-prep

docker compose up -d          # 启动（后台）
docker compose ps             # 状态；等 STATUS 变成 (healthy)
docker compose logs -f api    # 跟踪日志
docker compose restart api    # 改完 .env 重启
docker compose down           # 停止并删容器（volume 保留）
docker compose up -d --build  # 改完代码/依赖后重建
```

启动后访问 <http://127.0.0.1:8765>。

`start_period` 给了 60 秒：首次启动要建库 + 加载向量模型，这段时间 `ps` 显示 `(health: starting)`
是正常的，别当成失败。

## 3. 数据在哪

| 内容 | 位置 | 说明 |
| --- | --- | --- |
| 数据库 `kb.sqlite` | named volume `job-prep_jobprep_data` | 挂到容器 `/app/data` |
| 向量模型缓存 | named volume `job-prep_model_cache` | 挂到 `/root/.cache/huggingface/hub` |
| 知识库、面经、收件箱、报告、评测集 | 项目目录下对应文件夹 | bind mount，Windows 侧可直接看 |

**数据库为什么不用 `./data` 绑定挂载**：WSL2 访问 `/mnt/e` 走 9p 文件系统，SQLite 的 WAL 在这种
文件系统上会随机报 `database is locked`，写入吞吐也掉一个数量级。放 named volume（ext4）才稳。

代价是不能直接拷目录。**现在已自动化**（2026-11-13 起），compose 里的 `backup` sidecar 每天
02:00 跑一次在线备份：

| 项 | 值 |
| --- | --- |
| 实现 | `scripts/backup_db.py`（SQLite backup API，不锁库不停服）+ `scripts/backup_loop.py`（常驻循环） |
| 产物 | `job-prep/backups/kb-<时间戳>.sqlite3.gz`，约 1.5MB / 178 spans |
| 保留 | 最近 7 份（`BACKUP_KEEP` 可调），先备份成功再删旧份 |
| 频率 | 每天 02:00（`BACKUP_AT_HOUR`），容器启动时先跑一次 |

为什么用 sidecar 而不是 Windows 计划任务：计划任务只在登录会话里可靠，本机 `schtasks` 还被安全策略
禁用；sidecar 跟 compose 一起起停、`restart: unless-stopped` 天然扛重启，服务没跑时也没有新数据可丢。

```powershell
docker logs job-prep-backup-1 --tail 5    # rc=0 + spans/blobs 数量
Get-ChildItem backups\*.gz                # 现有快照
scripts\backup.bat                        # 手动补一份（容器没跑会退回本机 venv）
```

**为什么不 `cp kb.sqlite`**：WAL 模式下最新写入在 `-wal` 里，单拷主库会"备份成功但少了最后几条"；
而且管道式拷贝可能拷到半写状态。backup API 做的是事务级一致性快照，跑完还会 `PRAGMA integrity_check`。

**恢复演练（实测过）**：

```powershell
docker compose stop api
python -c "import gzip,shutil;shutil.copyfileobj(gzip.open('backups/kb-20261113-133955.sqlite3.gz','rb'),open('restore.sqlite3','wb'))"
docker cp restore.sqlite3 job-prep-api-1:/app/data/kb.sqlite
docker compose start api
docker exec job-prep-api-1 python -c "import sqlite3;c=sqlite3.connect('/app/data/kb.sqlite');print(c.execute('PRAGMA integrity_check').fetchone(),c.execute('SELECT count(*) FROM spans').fetchone())"
```

验证要点：`integrity_check` 返回 `ok`，且 spans 数量与备份时一致（空库也能"恢复成功"，不看数量等于没验）。

**坑**：backup 服务挂 `jobprep_data` 时不能加 `:ro`。WAL 模式下即使只读，SQLite 也要建 `-shm`
共享内存文件，只读挂载直接报 `unable to open database file`。脚本内部用 `mode=ro` 打开，写权限只服务
于 `-shm` 映射。

## 4. 时区

容器默认 UTC。`docker-compose.yml` 里已经加了 `TZ: Asia/Shanghai`，**不要删**。

不设的后果不是"时间显示差 8 小时"这么轻：span 的 `start_ts` 会写成 UTC，混进历史数据
（本地时区写入）后，trace 列表按时间排序全乱，`按天统计` 会把晚上 8 点之后的数据算到前一天。
这问题排查起来非常费劲——数据都在，只是顺序和日期错了。

验证方式：

```powershell
docker exec job-prep-api-1 python -c "import datetime;print(datetime.datetime.now())"
```

输出应该和你手机上的时间一致。

## 5. 已知的几个坑

**volume 警告**：`up` 时会打印

```
volume "job-prep_jobprep_data" already exists but was not created by Docker Compose
```

无害。这个 volume 是首次部署时手工创建并导入了现有数据的（`docker volume create` + 拷贝
`kb.sqlite`），compose 只是不认识它的来源。要消除它，可以在 compose 里声明 `external: true`，
但那样换机器首次部署会直接失败，所以保留警告更划算。

**端口冲突**：容器占 8765。如果之前用 `start.bat` 在本地跑过，要先停掉本地的 uvicorn，
否则容器起不来（`port is already allocated`）。

**`ui` 服务已删除**：原来 compose 里还有个跑 Streamlit（8501）的 `ui` 服务，那是前端改 Vue
之前的旧界面，FastAPI 早就直接托管 `frontend/dist` 了。留着它只是白占一个容器和端口。

**镜像里没有 node/npm**：前端产物 `frontend/dist` 必须在构建镜像**之前**就在本地构建好
（`cd frontend && npm run build`）。`.dockerignore` 特意没有排除 `frontend/dist`，但排除了
`node_modules` —— 后者 15 万个文件，进了构建上下文会让 `COPY` 卡十几分钟甚至报路径过长。

## 6. 和本地直接跑的关系

两种方式不冲突，但**共用同一个 8765 端口，只能开一个**。

| | 容器 | 本地 `start.bat` |
| --- | --- | --- |
| 依赖隔离 | 完全隔离 | 用项目 `.venv` |
| 改代码生效 | 要 `--build` 重建 | 重启 uvicorn 即可 |
| 数据库位置 | named volume | `./data/kb.sqlite` |
| 适合 | 长期跑、给别人复现 | 开发调试 |

改代码时用本地跑更顺手；只想让它一直在那儿跑着，用容器。

**注意两边数据是分开的。** 容器里产生的对话/span 不会出现在本地 `./data/kb.sqlite`，反之亦然。
切换前如果要保留数据，先按第 3 节备份再导入。

## 7. Langfuse（自托管观测后端）

业务容器通过 OTLP 把 span 双写到 Langfuse；**本地 `kb.sqlite` 仍是唯一事实源**，
Langfuse 只是分析层副本，它挂了业务与本地面板完全无感。

```powershell
$env:PATH = "E:\Docker\resources\bin;" + $env:PATH

# 首次：建共享网络（api 容器靠它用服务名访问 langfuse-web）
docker network create obs

# 启动 / 停止（--env-file 必须带，密钥在 .env.langfuse 里）
docker compose -f deploy/langfuse/docker-compose.yml --env-file deploy/langfuse/.env.langfuse up -d
docker compose -f deploy/langfuse/docker-compose.yml --env-file deploy/langfuse/.env.langfuse ps
docker compose -f deploy/langfuse/docker-compose.yml --env-file deploy/langfuse/.env.langfuse logs -f langfuse-web
docker compose -f deploy/langfuse/docker-compose.yml --env-file deploy/langfuse/.env.langfuse down   # 卷保留
```

起来后浏览器打开 <http://127.0.0.1:3000>，登录 `admin@local.dev / Jobprep-Lf-2026!`
（首启自动创建，见 `.env.langfuse`）。业务侧配置在根目录 `.env` 的
`TRACING_ENDPOINT / TRACING_HEADERS / OBS_BACKEND / LANGFUSE_*` 各变量。

### 对账与验收

BatchSpanProcessor 导出失败是**静默丢弃**（这是刻意的：观测挂了不能影响业务），
所以别拿 Langfuse 当完整事实源，要定期和本地对账：

```powershell
# 本地 span 数
docker exec job-prep-api-1 python -c "import sqlite3;print(sqlite3.connect('/app/data/kb.sqlite').execute('SELECT count(*) FROM spans').fetchone())"
# Langfuse 侧：GET /api/observability/backend 看 reachable；面板里 trace 数对照
```

验收清单：跑一轮真实对话后 Langfuse 出现新 trace 且树结构与 Traces.vue 一致；
停掉 langfuse-web 再对话，业务不受影响、本地 span 照常落库。

### 镜像拉取的坑（2026-11-13 实测）

- `docker.io` 的 minio/bitnami 被 registry 返回 `denied`（加速站限制），换 `cgr.dev/chainguard/minio` 直连可用；
- `docker.langfuse.com` 可拉但网络不稳，中途 EOF 时**重跑同一条命令即可续传**；
- Docker daemon 走 `127.0.0.1:7890` 系统代理，代理软件没开时 cgr.dev 会报
  `connectex: No connection could be made`——先把代理开着再 pull。

### 首次部署踩过的三个坑（改配置后要 `--force-recreate langfuse-web`）

1. **v4.79 的初始化要求 `LANGFUSE_INIT_ORG_ID` 和 `LANGFUSE_INIT_PROJECT_ID` 必须显式设置**，
   只给 NAME 的话整组 INIT 变量被静默忽略（web 日志有 warn，业务无报错，表现是注册页而不是自动建号）。
   且 compose 的 `environment` 是白名单——`.env.langfuse` 里加了变量还不够，
   必须在 compose 里也列出（本文件已列全，别删）。
2. **web 必须设 `HOSTNAME: 0.0.0.0`**。Next.js standalone 拿 Docker 注入的 HOSTNAME（容器主机名）
   当绑定地址，只绑容器 eth0 IP；跨网络（obs）访问它的另一块网卡 IP 会 Connection refused。
   症状：容器内 `wget 127.0.0.1:3000` 被拒、宿主 curl 得到空响应（exit 52）。
3. **改 `--env-file` 内容不会触发容器重建**（compose 不比对 env-file 内容）。
   改完密钥/初始化配置后要 `up -d --force-recreate langfuse-web`。

### 验收结果（2026-11-13）

一轮真实编排对话后：Langfuse 收到 41 条 observations（AGENT/CHAIN/TOOL/RETRIEVER/GENERATION
类型齐全）；`v2/observations` 接口用固定 key 鉴权 200；停掉 langfuse-web 再跑一轮对话，
业务 200 正常回答、本地 spans 照常 +9，重启 web 后自动恢复。

## 8. API 鉴权与审计（2026-11-13 起）

`.env` 里的 `APP_TOKEN` 开启后，**所有 `/api/*` 都要求令牌**；`/health`、前端静态页、
`/docs` 放行（healthcheck 不能带 token，页面本身没有数据）。

- 浏览器：首次打开页面会弹框要求输入令牌，存 localStorage 后自动带上，只需输入一次；
- curl / 脚本：`-H "X-API-Token: <token>"` 或 `-H "Authorization: Bearer <token>"`；
- `APP_TOKEN` 留空 = 完全关闭鉴权（本地脚本/测试零开销）；
- MCP 不受影响：stdio 靠进程边界，HTTP 侧用它自己的 `MCP_TOKEN`。

审计（`audit_log` 表）只记两类请求：**写操作**（POST/PUT/DELETE/PATCH，含被参数
校验拒绝的）和**被拒的 401**。GET 不记；body 一律不落库——审计表不存简历内容。
查询接口：`GET /api/obs/audit?days=7`（返回 total、denied_401 和明细）。

```powershell
$token = "<你的 APP_TOKEN>"
# 看最近被拒的请求
curl.exe -s --noproxy "*" -H "X-API-Token: $token" "http://127.0.0.1:8765/api/obs/audit?days=1"
```

## 9. 观测噪音：FastAPI 自带埋点（2026-11-13 定位并关闭）

**现象**：Langfuse 里 12 小时积了 8535 条 span，其中 8504 条（99.6%）是
`fastapi.endpoint` / `fastapi.dependencies` / `fastapi.serialization` / `GET /health`，
真实业务 span 只有 23 条。根源是 FastAPI 0.162+ 内置 ASGI telemetry：**激活条件就是
「全局 TracerProvider 已被配置」**，而 `tracing.configure()` 之前调了 `trace.set_tracer_provider()`，
于是 Docker healthcheck（每 15s 一次）每个请求都生成 4 条 span。

**修法**：`configure()` 不再注册全局 provider。我们所有 span 都由 `_tracer` 直接从自有
provider 取，本来就不依赖全局；副作用是"只有显式埋的点才出去，第三方库自动埋点一律不出去"。
回归测试 `test_global_provider_stays_unconfigured` 锁住这条约束（断言全局 tracer 拿到的
是 `NonRecordingSpan`）。

**顺带纠正一个误判**：此前以为"每个 span 被重复导出 15 倍"。实际是 v2 observations 接口
用游标分页、我用了 `page=` 参数，15 页返回同一批数据；外加 ClickHouse `events_full` 是
ReplacingMergeTree，`count()` 会把未合并的副本算进去（raw 232 / uniqExact 23）。
**对账要用 `uniqExact(span_id)` 和本地 `count(*)` 比，不要用 raw `count()`。**

```bash
# 正确对账姿势
docker exec langfuse-clickhouse-1 clickhouse-client --query \
  "SELECT uniqExact(span_id) AS spans, uniqExact(trace_id) AS traces FROM default.events_full"
docker exec job-prep-api-1 python -c "import sqlite3;print(sqlite3.connect('/app/data/kb.sqlite').execute('SELECT count(*),count(DISTINCT trace_id) FROM spans').fetchone())"
```

清理历史噪音（Langfuse 副本可随时重建，本地库才是事实源）：

```bash
docker exec langfuse-clickhouse-1 clickhouse-client --query "TRUNCATE TABLE default.events_full"
docker exec langfuse-clickhouse-1 clickhouse-client --query "TRUNCATE TABLE default.events_core"
```

## 10. CI 门禁（2026-11-13 起）

两个 workflow 分工明确：

| 文件 | 内容 | 触发 | 成本 |
| --- | --- | --- | --- |
| `.github/workflows/ci.yml` | `pytest` 全量 291 用例 + 前端 `npm ci && build` | 每次 push/PR | 零 LLM，约 3 分钟 |
| `.github/workflows/evals.yml` | 语法检查 + 检索快检 + 全量评测门禁 | 同上；全量需 `LLM_API_KEY` | 有 LLM 成本 |

- CI 用 `requirements-dev.txt`（= 运行时依赖 + pytest）。之前 pytest 只装在某个 venv 里，
  CI 上会直接 `command not found`——"我机器上能跑"的典型形态；
- 固定 `TZ: Asia/Shanghai`：span 的 `start_ts` 是本地时间字符串，换时区跑断言会飘；
- 预热 bge-small-zh-v1.5 失败不阻断（embedder 有 FTS 降级路径），模型缓存在 Actions cache；
- **注意**：workflow 只有推到远端才会执行，本地改完不 push 等于没门禁。
