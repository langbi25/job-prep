## 一、先说透"飞轮"是什么

你说的飞轮，我理解成三层闭环，当前项目只转了半圈：

```
【现状·半圈】
投喂面经 → 抽题入库 → 模拟面试 → 错题/掌握度 → SRS 复习
（数据在流动，但"流过去"之后没有回头影响"下一次投喂前我该干什么"）

【要补的两圈】
第 2 圈 · 投喂即分析：
  每投一份面经，系统立刻对照"我当前的状态"产出一份作战地图——
  逐题回答三个问题：我有卡吗？我掌握度多少？我预计能答几分？
  同时列出缺口清单（高频但无卡的题、有卡但掌握度低的题）。

第 3 圈 · 真实结果回录：
  面试完了把真实被问到的题 + 自己的感受回录进系统，
  系统对比"预测 vs 真实"，校准自己的判断——
  这才是飞轮的完整闭环：系统给出的准备建议，被现实检验，越转越准。
```

**判断飞轮转没转起来的量化指标**（做进 Dashboard，不靠感觉）：

| 指标 | 含义 | 目标 |
|---|---|---|
| 题目覆盖率 | 题目池中有对应知识卡的比例 | ≥ 80% |
| 高频无卡题数 | freq≥2 但无卡的题 | → 0（这是最优先的进化信号） |
| 预测命中率 | 作战地图的预测档位 vs 模拟面试实际档位 | ≥ 70% |
| 真实校准偏差 | 预测 vs 真实面试回录的差距 | 趋势收敛 |

## 二、飞轮引擎（后端，先做）

复用现有地基（rag_service 混合检索、context_builder 上下文组装、mastery 数据），
新增三个能力：

### 1. 作战地图（coverage_service）

**触发**：面经确认入库时自动跑一次；之后可手动重跑。

**产出**（每场面试一份，存 `coverage_reports` 表，前端直接渲染）：
- 逐题：匹配到的知识卡（id + 掌握度）、错题历史、**基于我知识库组装的参考答案要点**
  （context_builder 已有这能力，复用）、预测档位（high/mid/low）、缺口标签
  （`无卡` / `有卡但弱` / `无错题记录`）；
- 汇总：预计本场得分、缺口 TopN、建议动作（按收益排序：先建哪张卡、先练哪道题）。

### 2. 进化方向报告（evolution_report）

回答"这个项目下一步该往哪进化"：
- **知识覆盖**：按方向/主题统计 卡片数 vs 题目池频次，找结构性空洞；
- **高频无卡题 TopN**：freq≥2 且无卡——每一条都是明确的进化指令；
- **薄弱卡排行**：mastery 低 + 有错题 + 高频的交集，是复习的第一优先级；
- **建议动作队列**：每条建议带"依据数据 + 预期收益"，与 HITL 审批打通
  （点一下就起草成 agent_action，批准后执行）。

### 3. 真实结果回录（interview_outcomes 新表）

面试回来后花 2 分钟回录：公司、日期、实际被问到的题（从题目池选或新建）、
自评每题表现、结果（过/挂/unknown）。系统自动算"预测 vs 真实"偏差并进趋势图。

### 新增 API

```
POST /api/coverage/{interview_id}/analyze   # 生成/刷新作战地图
GET  /api/coverage/{interview_id}           # 读取
GET  /api/evolution/report                  # 进化方向报告
POST /api/outcomes                          # 回录真实面试结果
GET  /api/flywheel/metrics                  # 飞轮四指标（Dashboard 用）
```

### 评测跟一块补

- 作战地图的预测档位也进 golden set 思路：有卡且 mastery≥3 的题预测 high，
  无卡预测 low——先用规则基线，LLM 增强后对比，防止"看起来智能其实不如规则"。

## 三、前端重构（后台管理系统风格）

### 技术选型（建议）

**Vue 3 + Vite + Element Plus + ECharts**，FastAPI 挂载编译产物（`app.mount("/", StaticFiles)`），
开发期 Vite proxy 到 8765。理由：Element Plus 是"后台管理系统"观感的标杆，
ECharts 的雷达/热力/趋势图直接满足可视化需求；构建产物纯静态，服务器上 Docker 不加服务。

### 页面规划（替换掉现在的 6 个 Streamlit 页签）

| 菜单 | 内容 | 对标现状 |
|---|---|---|
| 📊 总览 | 飞轮四指标卡、雷达图、7 天活动热力、待办（到期卡/待审批/待抽取） | tab6 雷达 |
| 📥 采集中心 | 投喂表单 + **状态机看板**（待抽取/已抽取/已确认/丢弃 四列泳道） | tab1 |
| 🗺 作战地图 | 选面经 → 逐题卡片（掌握度/参考要点/缺口标签/预测档位）+ 汇总 | **新增（飞轮核心页）** |
| 🧮 题目池 | 表格：频次排序、有无卡标记、合并管理、按方向/公司筛选 | tab3 |
| 📚 知识库 | 卡片 CRUD、标签筛选、全文+语义搜索、mastery 进度条 | tab2 |
| 🎤 模拟面试 | 组卷向导 → 答题界面（倒计时/逐题/追问展示）→ 结果报告页 | tab4 |
| 🔁 复习中心 | SRS 今日队列、错题管理、归因统计 | tab5 |
| 🧬 进化报告 | 覆盖率趋势、高频无卡题排行、建议动作队列（接 HITL 审批） | **新增** |
| ✅ 审批中心 | agent_actions 列表 + 批准/驳回（现在藏在 tab5 底部，太隐蔽） | tab5 底部 |
| ⚙️ 设置 | LLM 配置状态、评测结果图表（band_accuracy 趋势/检索三档）、数据备份 | 新增 |

交互底线：所有写操作（建卡/确认/审批/回录）保持现在的 HITL 语义不变。

### 兼容策略

Streamlit 保留为 `ui_legacy/`（旧入口可切回），新前端成熟后下线。
FastAPI 同时挂 `/`（新前端）与 `/legacy`（可选）。

## 四、开工顺序（建议）

| 阶段 | 内容 | 理由 |
|---|---|---|
| **A. 飞轮引擎**（先做） | coverage_service + evolution_report + 3 个 API + 旧 UI 临时展示 | 先让数据能力就位，否则新前端是"好看的房子没家具"；工作量约一个下午 |
| **B. 前端骨架** | Vue3 工程搭建 + 布局/路由/登录页占位 + 总览页（接飞轮指标） | 框架立起来 |
| **C. 高频页面** | 采集中心 → 作战地图 → 模拟面试（按使用频率排序迁移） | 三个页面覆盖 80% 日常操作 |
| **D. 其余页面 + 下线旧 UI** | 题目池/知识库/复习/审批/设置 | 收尾 |
| **E. 真实结果回录 + 校准闭环** | interview_outcomes + 预测命中率趋势 | 飞轮第三圈，需要你有真实面试后回录 |

A+B 可以并行推进；E 依赖你真实面试节奏，不阻塞前面。
