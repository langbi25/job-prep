# job-prep 使用说明书

> 面向"拿到这个项目的人"：从零启动、每个功能怎么用、日常节奏怎么安排。
> 环境：Windows / macOS / Linux 均可，Python ≥ 3.11（推荐 3.12+）。

---

## 一、这个项目是什么

一句话：**把你的面经、知识卡、模拟面试、错题、复习计划变成一条自动化流水线**，
LLM 负责抽题、评分、教练建议，关键写操作由你人工审批，全程有评测门禁兜底。

```
投喂面经 → LLM 抽题 → 你确认 → 题目池 + 知识卡
    → 模拟面试（LLM 当面试官评分）→ 错题归因 → 掌握度更新
    → SRS 安排复习 → 学习教练 Agent 生成今日计划（需你审批执行）
```

## 二、第一次启动（5 步）

```bash
# 0. 进入项目目录
cd job-prep

# 1. 建虚拟环境并装依赖（国内建议加镜像源）
python -m venv .venv
.venv\Scripts\activate                      # Windows
# source .venv/bin/activate                 # macOS / Linux
pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/

# 2. 配置 LLM（不配也能启动，只是 LLM 功能不可用）
copy .env.example .env                      # macOS/Linux: cp .env.example .env
#   编辑 .env，填入 LLM_API_KEY=sk-xxxx（默认 DeepSeek，可换任意 OpenAI 兼容服务）

# 3. 启动（终端 1，后端 + Web 系统一体）
uvicorn app.main:app --port 8765
#   首次启动会：建库 → 收编 knowledge/ 下的 md 卡片 → 下载 embedding 模型（约 90MB，
#   自动走国内镜像，只需一次）。看到 [startup] db ready 即成功。

# 4. 打开系统
#   浏览器打开 http://localhost:8765/ → Vue3 后台管理系统（推荐入口）
#   侧边栏 10 个页面：总览 / 采集中心 / 作战地图 / 题目池 / 知识库 /
#   模拟面试 / 复习中心 / 审批中心 / 改造方案 / 进化报告

# 5. 验证
#   http://localhost:8765/health → 看到 {"ok":true}
#   （旧版 Streamlit 前端仍可用：streamlit run ui/streamlit_app.py，端口 8501）
```

> 前端改版后需重新构建：`cd frontend && npm install && npm run build`（产物 dist/ 已随仓库提交，普通使用可跳过）。

**不想配 LLM？** 知识库管理、检索、复习调度、SRS 全部可用；不可用的只有：
面经自动抽题、模拟面试评分、教练建议这些"要花钱"的功能。

## 三、六个页签怎么用

### 📥 采集台（ tab1）——喂面经的地方

三种投喂方式，效果一样：

1. **直接粘贴**：把面经全文贴进文本框 → 提交；
2. **URL 投喂**：贴一个面经网页链接，后端自动抓正文（失败会自动降级为手动粘贴）；
3. **浏览器书签（bookmarklet）**：在任意面经网页上点一下书签，自动带 URL + 选中文字投喂。
   （页面上有现成的书签链接，拖到书签栏即可；部署到服务器后要把里面的
   `localhost:8765` 换成服务器地址。）

投喂后的流程：**待抽取 → LLM 抽出题目（公司/方向/轮次/题目）→ 你逐条确认或丢弃**。
确认后：面经落库、题目进"题目池"（相同题自动合并计数，出现次数就是面试频率）。

> 这是刻意设计的人工 QA 环节：LLM 抽取会有错漏，确认一次换来干净的题库。

### 📚 知识库（tab2）——你的知识卡片

- **建卡**：填标题 / 领域（backend / agent / bigdata / cs）/ 主题 / 问题 / 要点；
- 卡片同时生成两份东西：`knowledge/` 下的一篇 **Markdown 文件**（用 Obsidian 打开这个目录，
  就是你个人的知识库 Wiki，随便改，启动时自动同步回系统）+ SQLite 索引行（用于检索和统计）；
- 搜索是混合检索：关键词（FTS）+ 语义（向量），口语化的问法也能命中。

### 🗂 面经库（tab3）——已归档的面经和题目池

- 查看每场面经的原文、抽取结果、来自哪个渠道；
- 题目池按出现频次排序——**频次就是真实面试出现频率，复习优先级的直接依据**；
- 发现重复题可以在这里手动合并。

### 🎤 模拟面试（tab4）——核心练习场

1. **组卷**：选方向（backend / agent / bigdata）、可填目标公司（只出这家公司考过的题）、
   可贴 JD（按 JD 出题）、题量。薄弱主题权重 +2，公司真题优先；
2. **作答**：逐题口述或打字作答，每题提交后立刻得到四维评分
   （正确性 / 深度 / 结构 / 亮点）+ 点评 + 追问；
3. **结束**：自动生成整场报告（存到 `reports/`），并触发数据闭环：
   低分题进错题池、暴露的知识缺口自动起草补卡建议（等你审批）、相关卡片掌握度调整。

> 评分是严格模式：答非所问就是 0~2 分，不会客套。评分时会参考你知识库里同主题的卡片，
> 知识库没覆盖的主题不会因为"没提到知识库内容"被扣分。

### 🔁 复习·错题（tab5）——日常主战场

- **今日到期卡片**：SRS 间隔复习（1/2/4/7/15/30 天），点"记住 / 忘记"调整节奏；
- **错题池**：每道错题带归因（知识盲区 / 表达不清 / 理解偏差），解决后手动标记；
- **每日简报**：一张卡片看清今天该干嘛；
- **Agent 补救建议（底部）**：点"从最近一场面试起草建议"，教练 Agent 会基于你的报告
  起草动作（建卡 / 提前复习薄弱卡 / 合并重复卡 / 归档过时卡），**每条都要你点批准才执行**。

### 📈 雷达·冲刺（tab6）——看全局 + 定计划

- **掌握度雷达**：按主题看掌握度分布，弱项一目了然；
- **公司冲刺卷**：输入公司名，只出这家公司考过的题组卷；
- **学习教练 Agent**：点"生成今日学习计划"，Agent 自主调用工具查你的真实数据
  （到期卡、错题、薄弱主题、高频题），产出带数据依据、带时间预算的计划，
  全程轨迹可查。

## 四、推荐的日常节奏（面试前 2~4 周）

| 时机 | 做什么 | 在哪做 |
|---|---|---|
| 碎片时间刷到面经 | 随手投喂 + 确认抽题 | 采集台 |
| 每天开始 | 看每日简报 → 清到期卡片 | 复习·错题 |
| 每天一次 | 看教练 Agent 的今日计划，按它执行 | 雷达·冲刺 |
| 每 2~3 天 | 打一场模拟面试（可针对目标公司） | 模拟面试 |
| 面试结束后 | 处理教练起草的补卡 / 复习建议 | 复习·错题底部 |
| 周末 | 看雷达，找最弱的主题集中补卡 | 雷达·冲刺 |

数据闭环会自动把"模拟面试暴露的弱点"变成"明天的复习任务"，你只需要照着做。

## 六、常见问题（FAQ）

**Q：端口被占了？**
后端端口在 `.env` 里改 `APP_PORT`；前端 `streamlit run ui/streamlit_app.py --server.port 8502`。

**Q：首次启动卡在下载模型？**
embedding 模型约 90MB，自动走 hf-mirror 国内镜像，只需一次，之后缓存在
`~/.cache/huggingface/hub`。彻底离线也能用（检索自动降级为纯关键词）。

**Q：改了 `knowledge/` 里的 md，系统会丢我的修改吗？**
不会，反着来的：md 是事实源，启动时自动收编进 SQLite。掌握度、复习进度这些
运行时数据存在库里，不会被 md 覆盖。

**Q：LLM 调用报 401 / 超时？**
检查 `.env` 的 `LLM_API_KEY` / `LLM_BASE_URL`；DeepSeek 偶发超时重试即可。

**Q：模拟面试评分太严/太松？**
评分锚点在 `prompts/evaluate_answer.yaml`，改完跑 `run_evals.py --gate` 验证，
别凭感觉调（评测集会告诉你改坏了没有）。

**Q：数据都在哪？怎么备份？**
一切数据在项目目录里：`data/kb.sqlite`（索引与状态）、`knowledge/`（知识卡 md）、
`interviews/`（面经归档）、`reports/`（面试报告）。整个目录拷走即备份。

**Q：想清空重来？**
删 `data/kb.sqlite` 重启即可重建索引；`knowledge/` 里的卡片会自动收编回来。

## 九、模拟面试与复习中心怎么用

**模拟面试**（`/mock`）
1. 左栏组卷：选方向、填面试官人设（如"严厉的技术总监，专挑边界与权衡"）、贴 JD、指定公司冲刺。
   组卷会优先高频题 + 薄弱主题；题池不足时用 LLM 补题并入池。
2. 逐题作答：一题一屏，写完 `Ctrl+Enter` 提交；当场出四维评分（正确性/深度/结构/亮点）+ 点评 + 追问。
   留空提交 = 跳过（不计分）。
3. 交卷：生成报告（均分、通过评估、亮点/短板/建议）落 `reports/`，并自动写回错题本、
   调整相关卡片掌握度、缺口主题补卡。
4. 历史场次可随时打开回看，未交卷的会标"未交卷"。

**复习中心**（`/review`）
1. 顶部四个数：今日到期 / 未解决错题 / 待处理采集 / 近期模拟均分。
2. 主区是今日队列：先自己口述一遍 →「显示答案」对照要点 → 「记得 / 没记住」。
   记得 +0.5 掌握度并按 [1,2,4,7,15,30] 天排下次；没记住 −0.5，明天重来。
3. 右栏：未解决错题（可标记已解决）、薄弱卡片（低掌握度且有复习记录）。

## 十、项目进化环：让卡片长出"我真做过"的厚度

这一环解决的是"背得出答案"和"做过这件事"之间的差距。

**走一遍（约 1 天，可拆成多次）**

1. **填项目档案**：`改造方案` 页左侧，写清技术栈 / 模块 / 数据量 / 痛点 / 约束。
   档案越具体，方案越不像通用模版。存于 `data/project_profile.md`，可随时改。
2. **选题生成方案**：题目池任一行点「改造方案」→ 选中题目 → 生成（20~40 秒）。
   方案含：目标、现状推断（带依据）、4~7 步实施步骤、验收标准、可量化指标、
   简历 bullet、面试叙述、复盘文档大纲。正文落到 `docs/plans/plan-xxx.md`。
3. **采纳并真做**：点「采纳」→ 详情页「复制全文」，粘给 WorkBuddy 当施工单。
   边做边在方案的「实施记录 / 效果对比」里填真实数据。
4. **回灌**：做完回系统点「回灌实战经验」，写实施笔记（≥30 字，要有模块名、
   命令、数字、踩过的坑）→ AI 起草**实战卡**（pending）→ 审批中心批准 →
   入库并与原原子卡 `related` 互链。

**三条边界（别搞混）**

| 产物 | 是什么 | 去哪 |
|---|---|---|
| 原子卡 | 这道题的通用正确答案 | `knowledge/` |
| 改造方案 | 针对你项目的一次性落地计划 | `docs/plans/`，**不进知识库** |
| 实战卡 | 做完后的复盘，与原卡互链 | `knowledge/`（标题带【实战】） |

复习原子卡时顺着 `related` 就能看到自己的实战卡，答题自然从"标准答案"变成
"我们当时是这么解决的，指标从 A 到 B"。
