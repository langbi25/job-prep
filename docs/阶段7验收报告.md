## 二、① CI 评测门禁（GitHub Actions）

`.github/workflows/evals.yml`，两层设计：

| 层 | 触发 | 内容 | 成本 |
|---|---|---|---|
| `fast-checks` | 每次 push / PR | `compileall` 语法检查 + `run_evals.py --skip-llm`（检索两档） | 零 |
| `full-gate` | 同上，**需 secret** | 全量评测 + 门禁，不达标红 | 每次约百次 LLM 调用 |

关键设计决策：

- **没配 secret 不假绿**：`full-gate` 检测 `LLM_API_KEY` 不存在时打 warning 并跳过，
  而不是静默失败——"门禁跳过"必须可见，否则形同虚设；
- **embedding 模型走 actions/cache**（90MB，key `hf-bge-small-zh-v1.5`）+ HF 镜像；
- **CI 空库不需要种子数据**：卡片是 `knowledge/` 下的 md 文件，启动时 `sync_all()` 自动收编。
  "Markdown 是唯一事实源"这个设计在 CI 场景直接兑现；
- `concurrency` 取消同分支的旧运行，连续 push 只跑最后一次。

启用方式：仓库 Settings → Secrets → Actions 添加 `LLM_API_KEY`。

## 三、② HITL 动作扩充：merge_card / archive_card

教练 Agent 现在能提 4 类动作（全部需人工审批）：`create_card` / `boost_srs` / `merge_card` / `archive_card`。

实现要点（每个都对应一个真实的坑）：

1. **kb_cards 加 `merged_into` 列**（老库用 `ALTER TABLE` 迁移，`db.init_db()` 幂等补列），
   重复卡归档后指向保留卡，可追溯；
2. **合并只做归档指向，不搬运内容**——搬运等于让 Agent 改写保留卡，风险大于收益；
   真要合并内容应该人在 Obsidian 里改 md。掌握度取 `MAX(两者)`、复习次数累加：
   复习进度不应因去重而倒退；
3. **归档必须删向量**：`embeddings` 是独立索引，不随 `status` 走。只改 status 不删向量的话，
   归档卡会继续从 hybrid 检索的**向量路**冒出来（FTS 路有 status 过滤，向量路没有）；
4. **归档必须同步 md frontmatter**：md 是事实源，不同步的话换台机器（或 CI 空库）重新
   `sync_all()` 时归档卡会以 active 身份复活。新增 `kb_service.update_md_meta()`；
5. **系统性清漂**：`ensure_all_indexed()` 启动时顺带清理"已归档卡/已删除题"的残留向量，
   返回值带 `stale_removed` 计数。

冒烟测试 `scripts/smoke_hitl.py`（零 LLM 调用）验证 6 项：造重复卡进索引 → merge 审批执行
（DB + 向量 + md 三处一致）→ 检索确认归档卡消失、保留卡在列 → archive 执行 →
自己合并自己被拦截（动作标 failed）→ 重复审批被拒。
