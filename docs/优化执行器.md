# 优化执行器 v1（P4）

## 定位

自进化闭环（评测 → 归因 → 分析 → **优化** → 再评测）的第四环。
P3 归因回答"为什么挂"，P4 回答"改什么、怎么改、改完怎么证明真的好了"。

```
attribution-*.json ──plan──→ 优化计划 ──draft──→ prompt 候选（LLM 改写+确定性校验）
                                     │
                                     ▼ evaluate
                        文件快照交换 → scoped eval → gate AND 基线对比
                                     │
                        通过 → 晋级(active) / 不过 → 回滚(rolled_back，文件还原)
```

## 设计决策

1. **运行时唯一事实源是 prompts/*.yaml**，prompt_versions 表只记生命周期与证据。
   上机 = 换文件（先存快照），回滚 = 还原快照；换文件后必须 `prompts.load.cache_clear()`。
2. **候选先过确定性校验再上机**（LLM 改写是概率性的，规则能挡的不放行）：
   占位符集合不变（渲染不炸）、花括号转义可渲染、output schema 字段说明仍在（JSON 契约不破）、
   长度 0.5x~1.8x（防跑飞）。校验失败落表 status=rejected，失败原因留档。
3. **晋级判据 = scoped gate 通过 AND 基线对比无回归**。
   只看 gate 会误判晋级（候选没改好但挂点恰好和基线一样）；
   基线对比按 scoped 指标逐项核，min 指标容差 ±0.02，max 指标（如 gap_false_confident）无容差。
4. **scoped eval**：改 study_plan 只跑 agent_tasks。评测函数已抽到 `app/services/eval_suite.py`
   （run_evals.py 变薄 CLI，`from run_evals import gate` 兼容 ci_gate.py）。
5. **版本冲突保护**：文件版本 ≠ 候选父版本 → 拒绝上机（防止覆盖人工改动）。
6. **评测中途炸也回滚**：文件状态与表状态一致是本模块最硬的不变量。

## 可自动优化的 prompt（v1）

| prompt | 触发来源 | 评测 scope |
|---|---|---|
| study_plan | agent_tasks 失败（没引用/工具选错/格式违规…） | agent_tasks |
| evaluate_answer | scoring 失败（unattributed/context_degraded） | scoring |
| extract_interview | extract_judge 失败 | extract_judge |

检索类失败（retrieval_miss）不触发 prompt 改写——那是补卡/索引问题，进人工项（走审批闸门）。
工具 description 改写与记忆策略调整为 v2：需先有工具级评测，晋级判据才成立。

## 用法

```bash
python scripts/run_optimizer.py --plan                # 优化计划预览（零 LLM）
python scripts/run_optimizer.py --evaluate --yes      # 起草 → 上机 → 自动晋级/回滚
python scripts/run_optimizer.py --status              # 版本表（状态/gate/回归依据）
python scripts/run_optimizer.py --rollback 12         # 手动回滚 active 候选
```

单条命令串联闭环：`run_evals.py --attribute && run_optimizer.py --evaluate --yes`

## 版本生命周期

candidate →（校验拒绝）→ rejected
candidate →（上机）→ active（旧 active 转 retired）
candidate/active →（gate 挂 / 回归 / 评测异常 / 手动）→ rolled_back（文件已还原）
