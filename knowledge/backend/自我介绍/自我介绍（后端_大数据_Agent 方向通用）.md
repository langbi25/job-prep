# 自我介绍（后端/大数据/Agent 方向通用）

**Q：** 自我介绍

## 要点

- 结论先行：用一句话定位自己，例如「我是有 X 年经验的后端/数据开发，主攻（填入：实时数仓 / Agent 应用 / 高并发服务），最近一年在做（填入：具体项目名）」。
- 按「总—分—总」组织：先给个人标签（年限+方向+核心技能栈），再挑 2~3 段最有代表性的经历展开，最后一句收尾表达与岗位的匹配点。
- 每段经历用 STAR 压缩成 3 句话：背景与目标（业务量级：QPS/日活/数据量，填入真实数字）→ 我负责的技术方案（填入：Flink/Kafka/Redis/Agent 框架等具体组件）→ 量化结果（延迟降低 X%、成本下降 X%、可用性 99.X%）。
- 技术栈只报与岗位 JD 强相关的 3~5 个关键词，并各配一个「用过到什么程度」的佐证，例如「Flink 做过（填入：日均 X 亿条、Exactly-Once 保障）」，避免罗列名词。
- 挑一个最深的项目作为主线，讲清「我解决了什么别人没解决的问题」，例如（填入：数据倾斜导致的反压、Agent 工具调用重复、上下文压缩丢历史），体现技术判断力而非只报流水账。
- 主动埋钩子：在结尾留一个面试官容易追问的点（如「其中 Flink 状态后端选型踩过坑」），把自我介绍变成后续对话的引导，而不是背简历。
- 控制时长 1.5~2 分钟（约 350~450 字），语速平稳；简历上每条经历都要能对应到口述中的一句话，防止被追问时对不上。
- 收尾表达动机：说明为什么看这个岗位（业务方向 / 技术栈匹配 / 想深入的方向），一句话即可，不要展开成表忠心。

## 易错

- 流水账式复述简历时间线，没有重点和量化结果，面试官抓不到你的技术标签。
- 技术名词堆砌但说不出深度，一追问「具体怎么做的」就露馅。
- 时长失控超过 3 分钟，挤占后面技术题时间，且显得不会抓重点。
- 埋的钩子自己接不住，被追问项目细节时数字和组件名对不上。
