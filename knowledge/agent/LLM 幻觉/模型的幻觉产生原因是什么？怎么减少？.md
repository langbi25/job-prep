# 模型的幻觉产生原因是什么？怎么减少？

**Q：** 模型的幻觉产生原因是什么?怎么减少?

## 要点

- 幻觉指模型生成看似合理但与事实或输入不符的内容，分事实性幻觉（与客观事实不符）和忠实性幻觉（与用户输入或上下文不一致）两类。
- 预训练目标本质是最大化下一个 token 的似然，模型优化的是「像不像」而非「对不对」，缺乏事实校验机制，这是幻觉的根本来源。
- 训练数据存在噪声、过时信息和长尾知识覆盖不足，模型对低频实体只能靠模式补全，容易编造细节。
- RLHF 对齐会引入「讨好型」偏差：模型倾向给出用户想听的确定答案，而非承认不知道，从而放大幻觉。
- 解码策略影响幻觉率：高温采样、top-p 过大增加随机性；贪心解码虽稳定但可能重复错误，需按场景调参。
- RAG 是主要缓解手段：检索外部知识注入上下文，并用 prompt 约束「仅依据给定资料回答，资料不足时明确说不知道」。
- 工程上做事实校验与后处理：用工具调用/代码执行验证数值与链接，用另一个模型做 self-consistency 或多模型交叉验证。
- 训练侧可用 RLHF 惩罚幻觉、SFT 注入「拒答」样本；推理侧可加引用溯源（citation）要求模型标注答案出处便于核查。
- 评估上要用事实性 benchmark（如 TruthfulQA）和人工抽检结合，监控幻觉率而非只看流畅度，形成闭环迭代。

## 易错

- 只答「模型不知道所以编」，没区分事实性幻觉与忠实性幻觉，深度不够。
- 把 RAG 当万能药，忽略检索质量差时反而引入新幻觉。
- 被追问「如何量化幻觉率」时答不出评估方法。
- 忽略解码参数和 prompt 约束这些低成本手段。
