## 项目一：求职备战 Agent（job-prep，个人项目，可自由改造）

- 技术栈：Python 3.13 + FastAPI + SQLite（含 FTS5 全文索引）+ bge-small-zh 向量检索；前端 Vue3 + Element Plus；无外部服务依赖，单机跑。
- 核心模块：
  - 采集：面经投喂 → LLM 抽取题目 → 人工确认入池（question_pool / question_occurrences）
  - 知识库：Markdown 为唯一事实源（knowledge/*.md）+ SQLite 索引 + 向量；卡片=题目+要点+坑点+掌握度
  - 检索：FTS 关键词路 + 向量语义路 + RRF 融合；中文搜索走子串匹配 + IDF 排序
  - 面试：模拟面试（多轮问答、逐题评分、整体报告）、复习调度（SRS）、错题本
  - Agent：多 Agent 协作起草动作（建卡/提前复习/合并卡/归档卡），全部走 HITL 审批后执行
  - 飞轮：面经 → 作战地图（逐题覆盖/预测档位/缺口）→ 进化报告（高频无卡题）→ 覆盖率指标
- 现状规模：5 场面经、55 道题、7 张卡、覆盖率 5%
- 当前痛点：
  1. 服务层函数（如 kb_service / coverage_service）只能被 FastAPI 路由调用，没有统一的工具注册表与参数 schema，LLM 无法自主编排这些能力；
  2. 唯一的外部能力入口是 REST API，没有 MCP/Skill 层，接入 Claude Code、Cursor 等客户端要重复写胶水代码；
  3. 工具调用缺少统一的可观测性（入参/耗时/错误码），线上问题只能翻日志；
  4. 部分操作非幂等（如重复建卡、重复投喂），重试有副作用。
- 约束：单人维护、单机部署（阿里云 ECS 2C2G + Docker）、不能引入重型基础设施（不上 K8s、不上消息队列）、改动需保持现有 REST API 兼容。
