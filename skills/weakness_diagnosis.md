## 这个技能解决什么

"我哪里弱"最容易答成空话（"要多练习""加强基础"）。这个技能的产出必须是
**可证伪的判断 + 能立刻做的动作**，而不是情绪安抚。

## 步骤

1. `get_daily_brief` 拿基本盘：到期卡、未解决错题、近期面试均分、薄弱卡。
2. 根据基本盘选下钻方向，**最多查两个**（查多了就是漫游，用户等不起）：
   - 错题多 → `get_weak_topics` 看主题分布；
   - 均分低但错题少 → `get_top_questions` 看高频考点是否覆盖；
   - 想知道"到底记没记过" → `search_kb` 用具体主题检索。
3. `recall_memory` 确认已知偏好（比如用户说过只准备后端、不看算法），
   不要给出与用户目标无关的建议。
4. 归因：把薄弱点归到三类之一——**没学过**（知识缺口）/ **学过但调不出来**（提取失败）/
   **会但答不到点上**（表达问题）。三类对应完全不同的动作：
   - 知识缺口 → 建卡 + 入复习队列；
   - 提取失败 → 加间隔复习、换问法；
   - 表达问题 → 模拟面试追问。
5. 给三条以内的动作，每条写清楚"做什么、大概多久、做完怎么验证"。

## 输出契约

- 每条薄弱点必须有数字或具体题目/卡片佐证，不许出现"感觉""可能"；
- 每条动作必须能在系统里执行（建卡/复习/模拟面试），不许是"多看书"；
- 总数 ≤ 3 条。超过三条等于没重点。

## 禁止

- 不要把所有薄弱主题都列一遍——用户知道自己的问题，要的是优先级。
- 不要在这条技能里直接起草卡（那是 interview_ingest / draft_cards 的事），
  除非用户明确说"帮我建".
